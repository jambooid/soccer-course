# we2000的ai

在视频《Winning Eleven 2000 (ISS2)》中（视频链接：http://www.youtube.com/watch?v=j_STW_kRgbE），你观察得非常敏锐：**场上非玩家控制球员（AI）的站位与移动，确实高度依赖“球在场上的位置”（Ball Position Driven）**。



在 PS1 硬件性能有限的时代，WE 系列并没有使用复杂的神经网络或深层寻路，而是采用了基于 **“球坐标参照系（Ball-Relative Formation Framing）+ 有限状态机（FSM）+ 动态权重评分”** 的极简高效 AI 驱动架构。



### 一、 视频中球员 AI 的底层驱动原理分析

#### 1. 核心机制：以球为中心的“弹性网格”阵型系统

AI 球员并不是盲目追球，每个球员在阵型中都有一个 **基准锚点（Base Anchor Spot）**。



- **球的位置决定全局偏移量**：当球在场上移动时（如视频中 [[01:15](https://www.google.com/search?q=https%3A%2F%2Fwww.youtube.com%2Fwatch%3Fv%3Dj_STW_kRgbE%26t%3D75)] 德国队与巴西队的攻防演练），整个球队的阵型网格会以球的 $X$（纵向）与 $Z$（横向）坐标进行动态压缩或拉伸。

- **期望位置公式**：

  $$\text{DesiredPosition} = \text{BaseFormationPos} + (\text{BallPos} \times \text{Weight})$$

  这解释了为什么球在右路时，左侧边后卫会向中路靠拢，而前锋会根据球的推进程度同步整体压上或退防。

#### 2. 无球进攻 AI：基于视场与空间的射线评估

在视频中（如 [[02:57](https://www.google.com/search?q=https%3A%2F%2Fwww.youtube.com%2Fwatch%3Fv%3Dj_STW_kRgbE%26t%3D177)] 和 [[07:43](https://www.google.com/search?q=https%3A%2F%2Fwww.youtube.com%2Fwatch%3Fv%3Dj_STW_kRgbE%26t%3D463)] 的边路下底传中与前插），无球进攻球员会做出非常逼真的前插和跑位：



- **前插触发（Overlapping / Run-In）**：当持球人在前场，且无球球员前方一定锥形区域（Sector）内没有敌方防守人时，AI 触发“前插”状态。
- **传球路线评估**：持球 AI 会向潜在接球人发射射线（Raycast），如果射线路径上无敌方拦截者，且距离合适，即执行传球。

#### 3. 防守 AI：最近原则与区域封堵

视频中防守方并没有全员逼抢，而是井然有序：



- **第一防守人（Presser）**：距离球最近的 AI 切换为“逼抢/上抢”状态。
- **第二防守人（Covering）**：其余防守 AI 保持在各自的“弹性网格”锚点上，封堵传球路线或执行人盯人（Marking）。

### 二、 可行的技术实现步骤 (Implementation Steps)

如果你想在 3D 游戏引擎（如 Unity 或 Unreal）中复刻类似 WE2002/2000 的足球 AI，可以按照以下顺序实施：



**1.步骤 1：建立全局战术坐标系（Tactical Manager）：**核心基础：球坐标驱动。

1. 在场景中创建一个全局管理类 `MatchManager`，实时记录足球的 `Vector3 ballPosition`。

   

2. 定义标准阵型（如 4-4-2、4-3-3）的静态相对坐标。

   

3. 编写函数根据 `ballPosition` 计算全局移动偏移量，更新所有 22 名球员的当前“基准期望位置”（Base Target Position）。

   

**2.步骤 2：构建球员层级有限状态机（FSM）：**决策核心：状态切换。

为每个球员挂载 FSM，划分三大主状态：



- **持球状态（Ball Control）**：判断盘带、传球还是射门。

  

- **无球进攻（Offense Support）**：计算拉边、插上跑位或接应。

  

- **防守状态（Defense）**：逼抢、补位或退防。

  

**3.步骤 3：实现基于评价函数的动态跑位与传球逻辑：**智能体现：空间识别。

- **无球前插算法**：以球员正前方扇形区域为目标，利用射线检测（Raycast）检查障碍物。当 `障碍物数量 == 0` 且 `离对方底线更近` 时，给予高前插权重。

  

- **传球安全度计算**：持球 AI 扫描周围队友，评估 `与队友距离`、`传球角度`、`拦截线间距`，选择综合得分最高者传球。

  

**4.步骤 4：引入平滑阻尼与步态微调：**表现层：消除机械感。

- 使用 `Vector3.SmoothDamp` 或 `NavMeshAgent` 进行移动控制，避免 AI 在目标点更新时频繁骤停折返。

  

- 结合动态旋转平滑（如 `Quaternion.Slerp`），使 AI 在跟踪球位置的同时保持自然的身体朝向。

在足球游戏（如《实况足球》（Winning Eleven）或《EA Sports FC》）的防守系统底层架构中，**第一防守人（Presser / On-Ball Defender）上抢**与**第二防守人（Covering Defender / Co-Defender）协防**是保证 AI 阵型严丝合缝、层次分明的核心算法模型。



这一系统通常由 **全局防守协调器（Defense Tactical Coordinator）** 进行统一管理，结合 **几何计算、动态评价函数（Scoring Functions）** 和 **有限状态机（FSM）** 共同驱动。



下面为你详细拆解第一防守人与第二防守人的筛选算法、决策树及协作逻辑。



### 一、 整体防守 AI 架构概览

在每一帧（或固定决策周期，如 10Hz/20Hz），防守系统遵循以下流水线处理：



```
       [ 游戏全局状态: 对方持球 ]
                  │
                  ▼
   [ 1. 动态角色分配 (Role Assignment) ]
   ├── 筛选第一防守人 (Primary Presser)
   └── 筛选第二防守人 (Secondary Covering Defender)
                  │
                  ▼
   [ 2. 行为状态机执行 (FSM Execution) ]
   ├── 第一防守人: 接近 / 拦截 / 抢断 (Approach/Intercept/Tackle)
   └── 第二防守人: 封堵传球路线 / 补位包夹 (Block Pass Vector/Cover Gap)
                  │
                  ▼
   [ 3. 底层物理与移动微调 (Movement Steering) ]
```

### 二、 第一防守人（上抢）算法逻辑

第一防守人的核心职责是**限制持球人的空间与视野，逼迫其犯错或直接完成抢断**。



#### 1. 角色筛选逻辑（Who is the Presser?）

不是简单地找“距离球最近的球员”，而是一个综合评分公式（Score Evaluation）：



$$\text{Score}_{\text{presser}} = w_1 \cdot \text{Distance}(P, B) + w_2 \cdot \text{Time To Reach}(P, B) + w_3 \cdot \text{Angle Penalty} + w_4 \cdot \text{Role Weight}$$

- **Distance ($P, B$)**：球员 $P$ 到球 $B$ 的欧氏距离。
- **Time To Reach**：基于球员当前跑动速度向量（Velocity Vector）计算的“到达球当前/预测位置所需的最短时间”（考虑到加速度和转向延迟）。
- **Angle Penalty（夹角惩罚）**：如果球员在持球人正后方，即使距离近，上抢也容易被过或犯规，因此给身前或侧前方球员更高权重。
- **Role Weight（职业角色权重）**：中后卫（CB）在最后防线上通常有更严格的上抢门槛（避免失位），而后腰（DMF）或边后卫（SB）上抢权重更高。

#### 2. 第一防守人有限状态机（FSM）

确定第一防守人后，其内部 FSM 包含以下子状态：



```
       ┌────────────────────────┐
       │     靠近/贴近 (Approach)│
       └───────────┬────────────┘
                   │ 距离 < 靠近阈值 (e.g., 2.5m)
                   ▼
       ┌────────────────────────┐
       │     卡位/压制 (Jockey)  │
       └─────┬──────────────┬───┘
             │              │
  抢断成功率 > 70%           │ 对方突破/离脚过远
             ▼              ▼
       ┌──────────┐   ┌──────────┐
       │ 伸腿抢断  │   │ 应急扑抢 │
       │ (Tackle) │   │ (Slide)  │
       └──────────┘   └──────────┘
```

#### 3. 目标位置计算（Target Vector Math）

第一防守人并不是直接冲向球，而是冲向**拦截点（Intercept Point）**：



- 如果对方在带球高速推进：AI 计算射线相交点，向对方**带球路径的斜前方**插人，封堵其前进路线。

- 在贴近（Jockey）阶段：AI 的期望位置 $P_{\text{target}}$ 处于 **持球人坐标 $B$** 与 **己方球门坐标 $G$** 的连线上（保持在球与球门之间）：

  $$P_{\text{target}} = B + \text{Normalize}(G - B) \times \text{IdealDistance}$$

### 三、 第二防守人（协防）算法 logic

第二防守人的核心职责是**补位、封堵传球路线（Passing Lanes），或在玩家指令下配合形成“双人包夹”**。



#### 1. 触发与角色筛选（Selection Logic）

第二防守人的筛选通常受 **玩家输入（按住协防键/双人压迫键）** 或 **AI 自主战术决策** 触发：



1. **排除第一防守人**：已分配为第一防守人的球员不参与筛选。
2. **安全性校验（Defensive Safety Check）**：
   - **禁选原则**：如果是己方最后一名中后卫（Last Man），且离开后会导致中路出现巨大空挡，系统会**严格禁止**其作为第二防守人上抢。
3. **邻域扫描与评分**：在第一防守人周边设定一个 radius 区域（如 8-15 米），寻找能够与第一防守人形成**夹角 $60^\circ \sim 120^\circ$ 扇形包夹**的无球球员。

#### 2. 双重协防模式（Two Defensive Modes）

第二防守人主要有两种运行模式：**“切断路线模式（Lane Blocking）”** 和 **“包夹抢断模式（Double-Team Pressing）”**。



##### 模式 A：切断传球路线（Lane Blocking / Cover Zone - 常态 AI）

在常规防守下，第二防守人**不盲目冲向持球人**，而是通过射线检测（Raycasting）寻找敌方最有威胁的潜在接球人 $R$：



1. 计算持球人 $B$ 到接球人 $R$ 的传球向量 $\vec{V}_{\text{pass}} = R - B$。

2. 第二防守人移动至该向量的中途截断点，并在向量两侧建立一个“拦截保护区”：

   $$P_{\text{cover}} = B + \vec{V}_{\text{pass}} \times 0.6$$

##### 模式 B：包夹上抢（Double-Team Pressing - 玩家激活协防键）

当玩家按下“协防键”时，第二防守人的 FSM 强制由“防守/补位”切换为“协防（Co-Defense）”：



1. **动态夹角限制**：第二防守人向球奔跑，但移动路径会经过微调，使其奔跑向量与第一防守人的奔跑向量形成包围势态，防止两人跑在同一条线（Concurrence）上被对方一个变向同时过掉。
2. **失位风险评估（Over-Commit Warning）**：协防 AI 会实时监测持球人是否传球。一旦持球人将球传出，第二防守人立即**解除协防**，回归原本的阵型锚点（Base Anchor Spot）。

### 四、 一第一/第二防守人的协同状态转换代码（逻辑伪代码）

在游戏开发（Unity / Unreal Engine）中，第一与第二防守人的状态机及协调器伪代码结构如下：



C#

```
public class DefenseTacticalCoordinator : MonoBehaviour
{
    public PlayerAI primaryPresser;
    public PlayerAI secondaryDefender;
    public Transform soccerBall;
    public Transform ownGoal;

    void UpdateDefenseLogic()
    {
        // 1. 每帧刷新第一防守人 (上抢)
        PlayerAI bestPresser = FindBestPresser();
        if (primaryPresser != bestPresser)
        {
            if (primaryPresser != null) primaryPresser.SetState(AIState.ZoneDefense);
            primaryPresser = bestPresser;
            primaryPresser.SetState(AIState.PrimaryPressing);
        }

        // 2. 判断是否触发第二防守人 (协防)
        if (InputManager.IsCoDefenseButtonPressed() || TacticalNeedCovering())
        {
            PlayerAI bestCover = FindBestSecondaryDefender(primaryPresser);
            if (bestCover != null)
            {
                secondaryDefender = bestCover;
                // 状态机迁徙：从普通防守转为协防包夹
                secondaryDefender.SetState(AIState.CoDefensePressing); 
            }
        }
        else if (secondaryDefender != null)
        {
            // 释放协防按键，第二防守人归位[cite: 1]
            secondaryDefender.SetState(AIState.ZoneDefense);
            secondaryDefender = null;
        }
    }

    PlayerAI FindBestSecondaryDefender(PlayerAI excludePlayer)
    {
        PlayerAI bestCandidate = null;
        float minScore = float.MaxValue;

        foreach (var player in teamPlayers)
        {
            if (player == excludePlayer || player.IsLastDefender()) continue; // 避开最后一名防守人[cite: 1]

            // 评估指标：与球的距离 + 是否破坏防线结构[cite: 1]
            float distToBall = Vector3.Distance(player.transform.position, soccerBall.position);
            float angleToPrimary = Vector3.Angle(
                player.transform.position - soccerBall.position, 
                excludePlayer.transform.position - soccerBall.position
            );

            // 鼓励产生 60 到 120 度的侧向包夹角度
            float anglePenalty = Mathf.Abs(90f - angleToPrimary); 
            float score = distToBall + anglePenalty * 0.1f;

            if (score < minScore)
            {
                minScore = score;
                bestCandidate = player;
            }
        }
        return bestCandidate;
    }
}
```

### 五、 核心协同规则与防止 AI“傻跑”的优化技巧

在 3D 足球游戏开发中，仅仅实现上抢和协防容易出现防线脱节，还需要加入以下平滑优化规则：



1. **迟滞效应（Hysteresis Buffer）**：
   - 在第一防守人的筛选中加入 **权重缓冲（Score Margin）**。只有当新候选人的评分比当前第一防守人高出 15%-20% 时才进行切换。防止球在两名防守人中间微幅滚动时，AI 频繁颠簸切换角色。
2. **上抢/协防硬直限制（Attack Cooldown）**：
   - 当第二防守人上抢扑空（被过）后，强制赋予其 1.5 秒的 `Stun/Recovery` 状态，期间不可再次被选为第一或第二防守人，必须减速回跑[cite: 1]。
3. **补位链条联动（Cover Chain Effect）**：
   - 当第二防守人离开原阵型锚点去协防时，同线的第三防守人（如中后卫）必须向协防球员留下的空档方向**横移补位（Slide Cover）**，以保持整体防线的横向紧凑性。
