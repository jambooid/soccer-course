## 主转播镜头

### 构图

- 镜头位于边线一侧的高位斜俯位置，沿球场长轴斜向观察；远端球门和禁区常在画面上方，近端区域在下方。
- 主机位的朝向稳定，草坪条纹、边线和看台在连续镜头中保持相同消失点。这是“电视转播感”的主要来源。
- 画面优先同时保留持球人、可接应队友和防线，而非让球始终居中。常规镜头中主体通常位于水平方向的中部附近、垂直方向的下半区。
- 视野足以覆盖中场到一个进攻三区的大部分宽度；禁区附近仍能看见门将、后卫和传球线路。球在远景很小，读球依赖队服对比、影子、控制箭头与雷达共同补足。

### 跟随目标

主镜头遵循以下优先级：

1. 有稳定控球者时，跟随控球者的地面位置，并向其进攻方向前瞻。
2. 球处于传球、射门或松散滚动时，临时改为跟随球的预测落点，避免镜头滞后到球已出画面。
3. 控球归属改变后，不立即反向追逐；先确认短暂的控球稳定窗口，再平滑转向新进攻方向。
4. 目标接近边线、底线或球门时，夹取相机焦点，而不是让画面暴露球场外侧的大面积空白。

这解释了录像中“球在画面内有一定偏移但局面仍然完整”的效果：相机服务于进攻空间，而不是执行机械的球心锁定。

### 运动曲线

- **连续且有惯性**：常规推进使用低频平移。带球急转或短传时，画面不会同步折返；相机先缓入，再追上新的构图。
- **纵横联动，但横向优先可见**：攻防在场地宽度方向转移时，主镜头平移尤为明显；沿进攻方向推进时，焦点也会前移，以保证下一层防线先进入画面。
- **静止区**：中场短距离盘带、无球争抢或球回传时，焦点应在死区内维持，不产生细碎抖动。
- **边界行为**：接近底线和边线后，球/球员可以继续向画面边缘运动，但相机停止。边界不是硬切，也不应以反向平移把主体重新推回屏幕中心。
- **固定镜头语法**：主机位不做跟球旋转、频繁 FOV 呼吸、手持震动或每次传球的快速拉近。射门的视觉强调应交给事件镜头和 HUD，而不是破坏比赛可读性。

## 事件镜头与节目节奏

| 状态 | 进入条件 | 相机行为 | 退出条件 |
| --- | --- | --- | --- |
| `BROADCAST` | 开球、普通控球、门球、角球、补时 | 高位斜俯固定朝向，带前瞻的受限平移。 | 进入禁区、射门、扑救、进球或哨响。 |
| `ATTACKING_THIRD` | 控球者/球稳定进入进攻三区 | 保持与主镜头同侧和同向；可略收构图，但不切换为低机位。 | 球离开危险区域，或触发关键动作。 |
| `SHOT_HOLD` | 射门起脚至门将接球/球出界/入网 | 冻结主镜头的跟随目标或降低跟随速度，留出球路和球门；不要追着高速足球大幅甩镜。 | 结果确定。 |
| `SAVE_OR_MISS` | 扑救、打偏、击中门框 | 主镜头可停留很短时间用于确认后果；随后直接返回重启构图。 | 重启状态已稳定。 |
| `GOAL_RESULT` | 进球判定 | 切至较低的球门侧/侧后方近景，展示门将、射手或庆祝；比分/HUD 同步更新。 | 庆祝展示窗口结束。 |
| `REPLAY` | `GOAL_RESULT` 的展示窗口之后 | 播放已记录的球与球员视觉快照，优先用球门侧方、后方或低角度；可用一到两个切点，不要实时追踪。 | 回放完成，切至开球构图。 |
| `SET_PIECE` | 定位球、开球、比赛重新开始 | 回到高位主镜头，先稳定构图再允许输入。 | 球进入比赛。 |

录像中的低位球门镜头主要承担“结果确认”和“回放”，不是每一次射门都立刻替换主视角。因此首版应优先保证 `BROADCAST -> SHOT_HOLD -> GOAL_RESULT -> REPLAY -> SET_PIECE` 这一链路，其余模式可以共用主镜头参数。

## 建议的实现契约

当前 [match3d_game.gd](../scenes/world3d/match3d_game.gd) 已具备固定旋转、受限前瞻、指数平滑、焦点死区和边界夹取：`CAMERA_SCREEN_X_OFFSET` / `CAMERA_SCREEN_Z_OFFSET` 负责主体屏幕锚点，`CAMERA_CARRIER_LOOKAHEAD_SECONDS` / `CAMERA_BALL_LOOKAHEAD_SECONDS` 负责控球者与无主球前瞻，`CAMERA_FOCUS_DEADZONE_*` 消除小幅盘带抖动，`CAMERA_FOCUS_*` 负责不越出球场。远端（画面上方）的 `CAMERA_FOCUS_Z_MIN` 设得更宽，避免球进入远端半场时机位过早停止。高速无主球会使用独立的 `CAMERA_FAST_BALL_FOLLOW_RESPONSE`。其限制是它仍只有单一实时跟随模式，尚未区分事件镜头状态或保留回放快照。

建议让相机导演器只消费比赛事件和表现快照，绝不反向修改比赛模拟：

```text
Match simulation
  -> presentation snapshot (ball, carrier, players, phase, event)
  -> camera director (shot state, target, offset, FOV, transition)
  -> Camera3D
```

必要输入：`carrier_id`、球的位置/速度、进攻方向、比赛重启阶段，以及 `shot/save/goal/out` 事件。回放缓冲区保存最近 `2-4 s` 的表现快照；回放期间 simulation 继续停在已判定的进球状态，或只渲染快照，不能重新推进规则 tick。

### 初始调参范围

这些是首轮录屏校准的起点，不是从抽帧反推的精确原作数值。

| 参数 | 建议 | 目的 |
| --- | --- | --- |
| 主镜头 pitch/yaw/FOV | 固定；FOV 约 `42-50 deg` | 保持同一电视机位和禁区可读性。 |
| 焦点屏幕锚点 | 主体位于水平 `45-55%`、垂直 `55-68%` | 给进攻方向和球路留出前方空间。 |
| 前瞻距离 | 正常带球约 `0.1-0.2` 个可视场地长度；高速球按速度增加并设上限 | 减少传球/射门时的追赶感。 |
| 死区 | 约 `0.03-0.06` 个可视场地宽度 | 消除盘带和控球切换中的微抖。 |
| 跟随响应 | 正常移动收敛约 `0.25-0.45 s`；球高速飞行时约 `0.12-0.25 s` | 慢而不拖，快而不甩。 |
| 模式最短保持 | 主镜头 `0.8 s`；射门保持至结果；进球展示 `0.8-1.5 s` | 防止事件密集时频繁切镜。 |
| 事件转场 | 主镜头内用 `0.15-0.3 s` 平滑；主镜头与回放/结果镜头使用硬切或极短淡变 | 保留 PS1 转播节奏，避免插值穿过球场。 |

## 验收方法

在 `1280x720` 录屏中逐项检查：

- 连续带球、横传和回传时，地平透视/镜头朝向不改变，且没有像素级来回抖动。
- 传球与射门时，球不会因相机滞后离开画面；带球人也不会被机械锁在绝对中心。
- 临近四条边界时，焦点停止在允许范围内，画面不露出球场外的大块空白。
- 射门阶段优先看见球路、门将和球门，而不是为了居中高速追球。
- 进球后能依序看到结果镜头、比分确认、只读回放与稳定的开球构图；回放不改变比分、时间、球权或球员状态。
- 门球、角球和补时可维持主转播构图与 HUD，不因状态文字或球员名字遮挡主要动作。

## 结论

这段 WE2000 录像的核心不是“镜头永远跟球”，而是**固定的高位转播机位 + 受限且有前瞻的构图平移 + 仅在结果时切到近景**。先把主镜头的稳定性、前瞻、死区和边界行为做好，再加入进球结果和只读回放，才能得到与参考一致的转播节奏；把每次触球都做成旋转、变焦或特写，会牺牲这类足球游戏最重要的场面可读性。
