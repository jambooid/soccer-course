# WE2000/2002 带球差距与实现记录

## 依据与范围

唯一行为依据是 [`We2000/2002带球分析`](We20002002带球分析.md)。本文不以旧的
`we2000-dribbling` 研究或 v2 计划作为需求来源。

目标是复现该文档描述的可读性，而不是模拟完整刚体足球：球在两次触球之间独立
滚动；控球、变向与失去球权都由有限状态和短时辅助决定。

## 实现前差距

| 参考机制 | 实现前状态 | 差距 |
| --- | --- | --- |
| 踢球、自由滚动、重新控制 | 已有独立球速、摩擦、触球计时和控制距离 | 转弯辅助在每帧直接拉球，转向不再只发生在触球点 |
| 常速与冲刺趟球 | 已有 JOG/SPRINT 的不同触球间隔、距离和推力 | 无需重做 |
| 8 向输入与触球窗口 | 输入为任意向量，触球没有离散方向分类 | 45/90/180 度动作不可预测也不可单测 |
| 45 度小切 | 只有通用转向 lerp | 没有保留动量的专门小幅修正 |
| 90 度扣球 | 没有专门分支 | 未在触球时清除旧球速，也没有 40% 级移动惩罚 |
| 180 度回扣 | 没有专门分支 | 没有支撑脚短锚定和延迟反向推出 |
| 前方防守者的安全微调 | 未实现 | 不会预测防守者移动或选择邻近安全通道 |
| 动画事件 | 低模角色当前没有骨骼/带球剪辑 | 只能用确定性的触球节拍器作为事件源 |

## 本次实现

### 1. 离散触球与有限状态

`DribblePhysics3D.quantize_direction()` 将 X/Z 平面意图映射到 8 个 45 度通道。
`Match3DGame` 在每个固定步记录最新通道，但只在触球计时器到期时消费它；球在
非触球阶段只受地面摩擦、正常前进球位补偿和抢断影响；不会把球拉回球员。

静止球员不会产生触球冲量。此前最小静止推球速度会在每个触球周期抵消地面摩擦，
导致开局和停球后的球缓慢漂离；现在只有实际移动速度超过 `0.12 m/s` 且有移动意图的
携带者才能把球推出去。松开方向后，球仅保留原方向并按地面摩擦自然减速，不会倒滚回脚边。
松键后的控球球员会以球的剩余地面速度自然跟随，直到两者停下；两者不会因控球关系互相拉回，且无外力或对手干扰时不会失去球权。
若受控携带者仍在控球、没有移动输入和对手干扰，球的地面速度经摩擦降到 `0.75 m/s`
以下时，球和球员会在当前位置同时归零，切断不可读的低速滑行尾巴；该规则不移动球的位置，
也不适用于回扣锚定或有外部干扰的情况。

带球状态由以下组合表达：

| 状态 | 表达方式 | 行为 |
| --- | --- | --- |
| 常速/冲刺 | `DribblePhysics3D.Mode.JOG/SPRINT` | 不同推球、触球间隔与控制距离 |
| 自由滚动 | `DribblePhase.FREE_ROLL` | 球独立积分，不按转向意图逐帧插值 |
| 180 度锚定 | `DribblePhase.TURNAROUND_ANCHOR` | 支撑脚侧在 `0.10s` 内平滑约束，随后才释放反向触球 |
| 丢球/争抢 | `carrier_id == -1` 或抢断方接管 | 取消所有锚定和排队触球状态 |

所有传球、射门、抢断、接自由球和开球路径都会调用
`_reset_dribble_turn_state()`，因此不会把上一次回扣的锚定状态带入新球权。

### 2. 45/90/180 度规则

`DribblePhysics3D.classify_turn()` 使用文档中的角度窗口：

- 25-65 度：45 度。保留普通触球的动量混合，移动速度乘以 `0.95`。
- 65-120 度：90 度。触球瞬间丢弃旧球速，沿新通道以 `0.80` 的推球量重新推出；
  球员速度乘以 `0.60`。
- 135-180 度：180 度。先在旧前进方向反侧的支撑脚位置锚定 `0.10s`，再以 `0.62`
  的推球量沿新通道释放；球员速度乘以 `0.15`，并锁定位置/方向输入 `0.20s` 后才重新起步。

速度惩罚只在一次触球时应用，替换了原先在玩家每帧大角度输入时反复扣速的逻辑。

### 3. 防守者预测微调

`steer_away_from_defender()` 对前方 4.2 米内最近防守者做 0.22 秒位置预测，并在
请求通道及其左右相邻 45 度通道中评分：保留输入前进意图、远离防守者、提升预测
后的净空。它只在触球时执行，所以不会产生持续的自动转向。

## 后续接入方法

当前 `Player3DView` 是程序化低模展示，没有可标记脚触球帧的骨骼剪辑。接入真正的
带球动画时，保留当前物理状态机和分类函数，只把 `dribble_touch_timer` 的到期来源
替换为动画剪辑中脚碰球帧的事件；事件调用应在下一个固定物理步消费已排队的 8 向
意图。这样渲染帧率不会改变球的判定结果。

建议顺序：

1. 为 JOG、SPRINT、90 度扣球和 180 度回扣制作带明确脚触球帧的剪辑。
2. 将剪辑事件连接到当前触球入口，保留固定步中的一次性冲量计算。
3. 依据录像调节 `turn_speed_multiplier`、`turn_touch_multiplier` 与锚定时长，而不是
   把球改成逐帧跟随角色。
4. 在人机对抗中记录丢球距离、转身耗时和冲刺趟球距离，按技术属性分层校准。

## 验证

`features/match3d/tests/test_runtime.gd` 覆盖：

- 输入在下次触球前只排队，不逐帧转球；
- 180 度锚定与反向释放；
- 90 度清除旧前向球速并施加横向触球；
- 8 向 45/180 分类；
- 前方防守者选择前进斜向安全通道。

运行：

```sh
godot --headless --single-threaded-scene --audio-driver Dummy --path . -s features/match3d/tests/test_runtime.gd
godot --headless --single-threaded-scene --audio-driver Dummy --path . -s features/match3d/tests/test_physics.gd
```
