## 参考画面的组成

### 1. 比赛空间

- 真实的球场纵深：草坪明暗条带、白线、禁区、球门网、跑道、广告牌、看台、顶棚和灯光共同形成尺度感。
- 镜头是固定高度的广播斜俯视，但会沿球的方向平滑移动，并在球门、冲撞、扑救、进球时切近景。
- 远景中球员很小，仍靠队色、深色轮廓、脚下阴影、头顶控制箭头和雷达保持可读。

### 2. 球员与动作

- 球员不是同一个几何体换颜色：至少有肤色/脸型、发型、球衣条纹、号码、守门员服装、裁判服装和体型差异。
- 常规跑动之外，画面明确展示护球、铲球、倒地、射门、门将扑救、庆祝、冲撞和站位恢复。
- 球和球员的接触有“准备、触球、飞行、落地/扑救、重新开球”的节奏，而不是瞬时传送。

### 3. HUD 与转播层

- 顶部：双方国旗、比分、半场时钟、补时提示。
- 底部左右：当前球员姓名、位置缩写、体力/状态色条；中下方：雷达小地图和控球/切换反馈。
- 状态字样：`Replay`、`GOAL KICK`、角球、`SAVE`、`LOSS TIME` 等，将规则状态直接翻译为玩家能读到的事件。
- 进球后：比分大字、庆祝镜头、回放；终场后：结果、半场比分、进球者/助攻者/分钟统计。

### 4. 节奏与声音

- 常规阶段保持连续控球；关键动作通过镜头切换、短暂停顿、哨声、门将扑救音、碰撞音和庆祝音乐形成峰值。
- 比赛前、半场、进球、终场都有独立的“节目段落”，因此十分钟录像不会只是同一镜头循环。

## 我们项目的已确认状态

- 3D 版本 `scenes/world3d/match3d_game.gd` 已能直接创建 11v11，并支持移动、冲刺、短传、长传、射门蓄力、切换、抢断、CPU 进攻、进球重开和 HUD。
- `features/match3d/tests/test_physics.gd`：`15 passed, 0 failed`；`test_runtime.gd`：`15 passed, 0 failed`。项目完整 headless runner 记录为 `136 passed, 0 failed`。
- `scenes/world3d/pitch_3d.gd` 已有草地、线、中心圈、简化球门、看台、环境光和阴影；`world3d_camera.gd` 已有边界夹取和跟球。

### 与参考的直接差距

| 领域 | 参考视频 | 当前项目 | 差距判断 |
| --- | --- | --- | --- |

## 缩小差距的实施方案

### 阶段 A：统一比赛权威与几何（P0，先做）

1. **单一比赛权威**：保留 `MatchSimulation/MatchSnapshot/MatchFlowAdapter` 作为规则与时间权威；让 3D 只消费快照。将 2D `ActorsContainer` 的 `build_presentation_snapshot()` 接入 `Match3DPresenter`，或将 3D 的可玩控制完整迁移到同一个 fixed-tick simulation；禁止长期维护两套独立传球、进球、重启公式。
2. **修正球门坐标契约**：以 `PitchConstants`/`Match3DRules` 的球门宽和球门线为源，生成可见柱、网、禁区和 scoring volume；增加“可见门宽 = 判定门宽”的测试。当前约 `1.44m` 对 `10.4m` 的错位必须先解决。
3. **补齐比赛状态**：3D 至少支持 `KICKOFF → FIRST_HALF → HALFTIME → SECOND_HALF → FULL_TIME`，时间可配置；补上球出界分类（边线球/角球/门球）、换边、补时和暂停。每个状态要有 HUD 事件和可测试的重启快照。
4. **建立可比基准**：固定输出 `1280x720/60fps` 和内部低分辨率模式；记录球员占屏像素、球门可见宽、镜头跟随延迟、HUD 安全区和关键动作事件延迟。自动化图形测试在 CI 继续用 headless，人工验收在真实 OpenGL 窗口进行。

### 阶段 B：先达到参考视频的“可读转播”（P1）

1. **相机导演器**：在现有 bounded follow 上加入状态机：`BROADCAST`、`ATTACKING_THIRD`、`GOAL_FOCUS`、`REPLAY`、`SET_PIECE`。进球前后保存 2-4 秒快照，回放只读快照，不写比赛状态；镜头切换要有最短保持时间，避免抖动。
2. **HUD 对齐**：复用 2D 的 `UI`/`RadarMinimap` 设计，给 3D 增加国旗、半场、当前球员姓名/位置、雷达、控球箭头、`SAVE/GOAL KICK/CORNER/LOSS TIME` 状态，以及结果页的半场比分和进球者/助攻者/分钟。操作提示应进入暂停/设置，不要常驻遮挡比赛。
3. **动作反馈层**：为 pass/shot/tackle/save/goal/out-of-bounds 建统一 event bus；事件驱动动画、音效、相机和 HUD，避免各模块自行写文字或播放声音。优先实现“触球前摇 → 接触 → 后果 → 恢复”的 0.2-0.8 秒动作窗口。
4. **角色可读性**：仍可使用低模，但增加可参数化材质槽：肤色、头发、球衣主/副色、条纹、号码、短裤、袜子、鞋、GK 套装、裁判套装。先做 4 个体型/头型和两队完整 11 人号码；不必一开始追求高面数。

### 阶段 C：补足“像一场比赛”的内容（P2）

1. **场馆资产分层**：广告牌和旗帜用低分辨率 nearest-filter atlas；看台用重复人群/座椅纹理；补跑道、灯杆、网格和阴影。资产按镜头重要性分 LOD，不把预算花在镜头不会看到的细节。
2. **门将和对抗姿态**：增加扑救方向、倒地、起身、铲球滑行、庆祝和碰撞失衡的关键帧；模型仍由 simulation 控制位置，动画只控制姿态。
3. **声音分层**：环境底噪、观众反应、哨声、触球、碰撞、门将扑救、进球庆祝、终场结果分别走 bus；按事件强度 duck 背景音乐。解说可最后用字幕/采样替代，不阻塞玩法。
4. **完整赛后流**：结果页显示半场比分、进球/助攻/分钟、控球或射门等最小统计，支持回到菜单/重赛；这正是参考视频最后 20 秒仍然有信息密度的原因。

## 验收门槛

- **玩法**：同一输入种子在 30/60/120Hz 渲染下逐 tick 快照一致；出界/角球/门球/半场/终场各有规则测试。
- **几何**：球门可见框、网、禁区和进球线共用同一尺寸常量；镜头永不露出球场外，球员不穿过球门/边界。
- **可读性**：1280x720 截图中，比分/时钟/半场/当前球员/雷达/事件字不重叠；任意时刻能区分两队、当前控制球员和球位置。
- **转播**：至少验证开球、普通进攻、射门被扑、进球、角球、门球、半场、终场 8 个导演状态；进球回放不改变比赛快照。
- **美术**：两队 11 人号码可辨，GK/裁判有专属颜色或轮廓；球员脚下有稳定阴影，球离地时阴影与高度同步。
- **性能**：目标机器 60fps；场上 22 名球员、球、网架、广告、看台启用时无明显掉帧；远景资产有 LOD 或实例化。

## 结论

项目的基础玩法已经接近“可玩的 WE2000 风格原型”，而不是零起点；最大差距在“完整的比赛节目和可读的 3D 转播表现”。优先级应为：**统一规则权威和修正球门几何 → 补齐 3D HUD/定位球/半场/终场 → 相机导演与回放 → 参数化球员/球衣 → 场馆、声音和细节**。这样每一阶段都能直接改善玩家看到和感受到的结果，也能避免把成熟 2D 规则与更简化的 3D 规则继续分裂。
