## 1. 文档概述

### 1.1 产品定位

一款 2D 俯视角街机足球游戏，以 WE2000（Winning Eleven 2000）的设计哲学为参照——**手感优先、判定清晰、AI 可信、球员有个性**。玩家通过简洁的操作体验足球的攻防博弈，而非追求物理仿真。

### 1.2 核心设计理念

源自 WE2000 的三条核心原则，贯穿所有需求的判断：

1. **确定性 > 随机性**：球轨迹、球员行为全由解析公式 + 参数驱动，"nothing is left to chance"。误差是可控的设计，不是 bug。
2. **手感 > 真实**：如果"真实值"导致手感差，直接 overrule 真实值。手感的判断标准只有一条：玩家觉得对不对，不是算得对不对。
3. **规则 > 仿真**：不模拟足球的物理过程，用确定性规则 + 可控噪声来创造可阅读、可学习、可掌控、有故事的博弈体验。

### 1.3 目标体验

- **上手快**：方向键 + 四个动作键（短传/长传/空档传球/射门），5 分钟就能玩明白。
- **有深度**：时机、站位、节奏的判断决定水平上限，而非手速。
- **每局不同**：球员能力差异 + 可控误差 + AI 行为差异 = 每场比赛有自己的故事。

### 1.4 游戏模式

| 模式 | 说明 |
|------|------|
| 单人对战 CPU | 玩家控制当前持球的球员，其余 10 名队友由 AI 控制 |
| 本地双人对战 | 两名玩家各控制己方持球球员，在同一台设备上对战 |
| 本地双人合作 | 两名玩家控制同一支球队，合作对战 CPU |
| 表演赛（CPU vs CPU） | 纯观看模式 |

### 1.5 核心玩法循环

```
选队 → 比赛（控球/传球/射门/防守） → 进球/失球 → 重新开球 → 时间结束 → 胜负结算
```

### 1.6 优先级定义

| 级别 | 含义 | 判定标准 |
|------|------|---------|
| **P0** | 必须有，没有就不算"完整游戏" | 直接影响核心玩法循环、每局都会碰到 |
| **P1** | 重要，显著提升游戏深度 | 改变玩法循环、创造新的决策维度 |
| **P2** | 有益，提升沉浸感和可信度 | 增强 AI 表现、球员辨识度 |
| **P3** | 锦上添花，有了更好 | 细节打磨、边缘体验 |

### 1.7 里程碑规划

| 阶段 | 目标 | 包含优先级 |
|------|------|-----------|
| **M1: 手感跃迁** | 操作跟手、传球准确、动作连贯 | P0 全部 + 部分 P1 |
| **M2: 玩法深度** | 动作有变体、对抗有博弈、球员有差异 | P1 全部 + 部分 P2 |
| **M3: AI 升级** | 跑位聪明、防守合理、球队像整体 | P2 全部 |
| **M4: 完整度提升** | 误差、节奏、反馈的全面打磨 | P3 全部 |

## 2. 比赛规则系统

**优先级：P0**

### 2.1 比赛时间

- 默认每场 **2 分钟**（街机节奏，非仿真 90 分钟）
- 可在设置中调整：1 分钟 / 2 分钟 / 3 分钟 / 5 分钟
- 时间在比赛进行中倒计时，进球庆祝、开球准备等时段时间暂停
- 终场哨响时如果比分持平，进入加时

### 2.2 加时赛

**优先级：P2**

- 常规时间平局后，进入 **30 秒加时**
- 加时采用"金球制"（突然死亡）：先进球一方立即获胜
- 加时仍平局则进入点球大战

### 2.3 点球大战

**优先级：P3**

- 双方各踢 **3 轮**点球
- 3 轮后仍平局，进入"突然死亡"轮次（一轮决胜负）
- 点球为简化玩法：玩家控制射门方向 + 力度，门将由 AI 扑救
- 点球大战的进球不计入球员统计，只决定胜负

### 2.4 进球判定

- 球整体越过球门线即为进球
- 进球后触发庆祝动画 + 比分更新 + 短暂停顿
- 之后双方球员回到各自半场，等待开球

### 2.5 出界与球权转换

**优先级：P1**

- 球飞出球场边界（上下左右四边）即出界
- 出界后由对方掷界外球（简化为在出界点附近开球，不需要专门的掷球动作）
- 球被门将在禁区内获得 → 门将开球（门球）
- 防守方将球踢出己方底线 → 对方角球
- 进攻方将球踢出对方底线 → 对方门球

### 2.6 开球

- 比赛开始、进球后、加时开始，都在中圈开球
- 开球方球员将球向前踢，比赛进入活球状态
- 开球前所有球员必须在己方半场
- 开球有短暂的"准备时间"，玩家可以调整位置

### 2.7 越位

**优先级：P0**

- 具备越位判罚：进攻球员在传球瞬间处于比倒数第二名防守球员更靠近对方球门的位置，且在对方半场内，即判越位
- 越位判罚有"主动参与比赛"的简化判定：仅当越位球员接到球或干扰防守时才吹罚
- 角球、门球、界外球无越位
- 越位后由对方在越位地点罚间接任意球（简化为在该点开球）

### 2.8 犯规和红黄牌

**优先级：P3（暂不启用）**

- 本期不引入犯规、红黄牌系统
- 铲球等激烈对抗的惩罚通过"硬直/失位"的机制体现，而非犯规哨
- 后续可作为可选扩展

## 3. 操作与控制系统

**优先级：P0（基础操作） / P1（进阶功能）**

> 参照 WE2000 操作设计：**方向键 + 四动作键**，控球时玩家自动控制持球球员，攻防两端操作逻辑统一。

### 3.1 操作方式

采用 WE2000 经典布局（方向键 + 四动作键 + 左右肩键）：

| 按键 | WE2000 对应 | 功能（持球时） | 功能（无球时） |
|------|-----------|--------------|--------------|
| **方向键 / 左摇杆** | 方向键 | 控制球员移动 + 朝向 | 控制球员移动 + 朝向 |
| **短传键（×）** | × 键 | 地面短传给队友 / 停球 | 上前逼抢 |
| **长传键（○）** | ○ 键 | 高空长传 / 传中（蓄力） | 滑铲 |
| **空档传球键（△）** | △ 键 | 直塞球（穿透防线送空档，蓄力） | 切换到最近队友 |
| **射门键（□）** | □ 键 | 射门（蓄力） | 门将出击 / 封堵射门 |
| **加速键（R1）** | R1 键 | 带球加速冲刺（消耗体力） | 加速跑动 |
| **特殊动作键（L1）** | L1 键 | 护球 / 假动作触发键 | 手动切换球员（精细切换） |

**默认键位（键盘）：**

- P1：方向键移动，`Z`=短传，`X`=长传，`C`=空档传球，`V`=射门，`Shift`=加速，`Tab`=特殊动作
- P2：WASD 移动，`1`=短传，`2`=长传，`3`=空档传球，`4`=射门，`Q`=加速，`E`=特殊动作

### 3.2 控球权自动切换

**优先级：P0**

参照 WE2000 的核心操作逻辑：**玩家始终控制当前己方持球队员**。

- **己方获得球权时**：控制权自动切换到接到球的那名球员
- **传球/射门后**：控制权暂留在出球队员身上，直到球被新的球员控制
- **球在空中/无人控制时**：控制权留在最后触球的己方球员
- **防守时**：控制权在"离球最近的己方球员"身上（可手动切换）
- **切换时**：有平滑的手感过渡，玩家方向输入会延续到新控制的球员上

> **设计意图**：玩家不需要手动管理"我现在控的是谁"——控球权在哪，玩家就在哪。这是 WE 系列"玩家像在踢球而不是像在操作一个人"的核心机制。

### 3.3 四键情境行为

同一按键在不同情境下触发不同动作，系统自动判断：

| 情境 | 短传键（×） | 长传键（○） | 空档传球键（△） | 射门键（□） |
|------|-----------|-----------|---------------|-----------|
| **己方持球** | 地面短传 | 高空长传/传中 | 直塞空档 | 射门（蓄力） |
| **己方半场门将持球** | 手抛球给队友 | 开大脚 | — | — |
| **球在空中可触** | 头球摆渡/胸部停球 | 顶给远处队友 | 凌空直塞 | 凌空射门/倒钩/头球攻门 |
| **无球、队友持球** | 要球（示意队友传过来） | — | 前插跑位示意 | — |
| **无球、对方持球** | 上前施压/逼抢 | 滑铲 | 切换到最近队友 | 封堵射门角度 |
| **门将（对方射门时）** | — | 倒地扑救 | 出击 | — |

### 3.4 辅助瞄准（磁性传球）

**优先级：P0**

- **短传（×）**：自动选择朝向方向上最近的队友，球路吸附到队友脚下
- **长传（○）**：自动选择距离合适的队友（优先远端、空位队友）
- **空档传球（△）**：自动寻找"队友前方的空当位置"，球送到队友跑动路线上，而非队友当前脚下
- 吸附强度与球员技术属性正相关：技术好的球员吸附范围更大、更精准
- 辅助强度可在设置中调整（低/中/高）

> **WE2000 设计精髓**：玩家不是"瞄准后传球"，而是"选择传球类型 + 方向"，系统自动找到最合适的目标。这降低了操作门槛，让玩家把注意力放在"决策传哪种球"上，而非"瞄准准不准"上。

### 3.5 力度蓄力

**优先级：P1**

- **射门（□）**：按住射门键蓄力，松开时释放。蓄力越久，球速越快、力量越大
- **长传（○）**：按住时间影响长传距离——轻点短，按得久传得远
- **空档传球（△）**：蓄力影响直塞球的力度和前送深度
- 蓄力有 UI 显示（球员脚下的力量条）
- 蓄力时间有上限（约 1.5 秒），达到上限后不再增加

### 3.6 输入缓冲

**优先级：P0**

- 玩家在动画播放期间按下的按键，会进入一个缓冲队列（窗口约 200ms）
- 当动画到达"可接受输入帧"时，检查缓冲队列，如果有有效输入则立即执行
- 目的：玩家不会因为"按早了几帧"而操作失效，提升操作跟手感
- 缓冲对短传、长传、空档传球、射门、铲球均有效

### 3.7 可取消窗口

**优先级：P1**

- 起手动作（射门起手、长传起手）的前几帧内，可以被新的输入取消
- 例如：按了射门发现角度不好，立刻按短传可以改为传球
- 取消窗口很短（约 6 帧 / 100ms），需要玩家快速反应
- 高风险动作（如铲球）没有取消窗口——一旦做出就必须承担后果

### 3.8 手动球员切换

**优先级：P0**

- 防守时，按空档传球键（△）手动切换到离球最近的队友
- 切换目标 = 距离球最近且在合理防守位置上的己方球员
- 切换时有视觉标识（当前控制球员头顶的箭头指示）
- 进攻时不需要手动切换——控球权自动跟随（见 3.2）

## 4. 球物理系统

**优先级：P0（基础） / P1（进阶）**

### 4.1 运动模型

- 球的运动采用**解析式弹道**：传球/射门的瞬间确定初速度，之后按固定公式运动
- 水平方向：受摩擦力影响逐渐减速（地面球）或匀速（空中球）
- 竖直方向：受重力影响做抛物线运动（2.5D 高度系统）
- 位置由闭式公式直接计算，而非逐帧积分——保证确定性和可预测性

### 4.2 球的状态

参照 WE2000，球有明确的状态区分，不同状态下运动规则完全不同：

| 状态 | 描述 |
|------|------|
| **被携带 (Carried)** | 球在球员脚下，跟随球员移动，有节奏的触球步点（不是粘在脚上） |
| **自由滚动 (Freeform)** | 球在地面或空中自由运动，受摩擦/重力影响 |
| **被踢出 (Kicked)** | 传球/解围后的球，有特定的初速度和轨迹 |
| **被射出 (Shot)** | 高速飞行的射门，带有特殊的碰撞和判定规则 |

> **WE2000 设计要点**："被携带"状态下，球不是固定在球员脚上，而是**每走几步触球一次**。两次触球之间球处于"自由滚动"的短暂状态——这就是防守球员可以抢断的窗口。球与球员的松耦合是 WE 系列手感的关键细节。

### 4.3 带球步点（Dribble Touch）

**优先级：P1**

- 球员带球时，球不是粘在脚上，而是每隔几步被触球一次
- 两次触球之间，球自由滚动一小段距离
- **触球频率**由球员的"技术"属性决定：技术好的球员触球更频繁（球离脚更近，更难被断）
- **触球距离**由速度决定：跑得越快，每步球离身体越远
- 防守方的抢断判定，只在球"离脚"的瞬间才有可能成功——这是抢断博弈的核心

### 4.4 传球物理

**优先级：P0**

对应 WE2000 的三种传球方式：

| 传球类型 | 触发 | 特点 |
|---------|------|------|
| **短传（×）** | 短传键 | 地面球，速度适中，精准度最高，距离近 |
| **长传（○）** | 长传键（蓄力） | 高空抛物线，落点远，落地后弹跳，需要接球球员调整 |
| **空档传球（△）** | 空档传球键（蓄力） | 地面快速直塞球，穿透防线，送到队友前方空当而非脚下 |

- 短传力度适中，由距离自动调节（球速 = 刚好滚到目标位置）
- 长传和空档传球的力度由蓄力时间决定
- 所有传球的力度也与球员的"力量"属性相关

### 4.5 射门物理

- 射门球速远大于传球，带力量加成
- 射门精度与球员射门属性正相关，与防守压力负相关
- 远射有更高的力量上限，但精度更低
- 射门有轻微的"误差弧"——不是 100% 指向瞄准方向（详见第 7 章 误差系统）
- 射门蓄力影响力量和精度：蓄力过满精度会略微下降

### 4.6 弹跳与碰撞

- 球碰到边界墙后反射，速度衰减
- 球碰到球员身体会反弹（非主动触球的情况下）
- 球落地弹跳：高度逐渐衰减，直到回到地面滚动
- 所有反弹使用简单的"反射 + 能量衰减"公式，不做连续碰撞检测

### 4.7 球的可预测性

**优先级：P2**

- AI 和玩家都应该能预判球的落点
- 系统提供球路预测 API（供 AI 和 UI 提示使用）
- 预测是准确的——因为轨迹是确定的公式
- UI 可显示球落点标记（辅助功能，可在设置中开关）

### 4.8 弧线球

**优先级：P3**

- 长传和射门可以带有轻微的弧线（侧旋）
- 弧线程度与球员技术属性相关
- 弧线让球员可以绕开防守球员，增加进攻手段

## 5. 球员系统

### 5.1 球员属性

**优先级：P1**

每个球员拥有以下基础属性（0-100 范围）：

| 属性 | 影响 |
|------|------|
| **速度** | 奔跑最大速度 |
| **力量** | 射门力度、传球距离、身体对抗 |
| **技术** | 传球精度、控球能力、停球质量 |
| **射门** | 射门精度、射门力量控制 |
| **防守** | 抢断成功率、防守站位 |
| **弹跳** | 争顶高度、头球能力 |
| **体力** | 全场持续跑动的能力，低体力时速度和反应下降 |

> **说明**：当前版本只有速度和力量两个属性，需要扩展到完整的 7 维属性体系。

### 5.2 球员位置/角色

每队 11 人（1 门将 + 10 名场上球员），默认阵型 4-4-2：

| 位置 | 数量 | 职责 |
|------|------|------|
| **门将 (GK)** | 1 | 守门、扑救、开球 |
| **边后卫 (RB/LB)** | 2 | 边路防守、插上助攻 |
| **中后卫 (CB)** | 2 | 中路防守、争顶、解围 |
| **边前卫 (RM/LM)** | 2 | 边路进攻、传中、回防 |
| **中前卫 (CM)** | 2 | 组织、传球、衔接攻防 |
| **前锋 (ST/CF)** | 2 | 进攻、射门、突破 |

> 阵型可在赛前选择（4-4-2、4-3-3、3-5-2、5-3-2 等），不同阵型影响球员角色和归位点。

### 5.3 球员动作

球员可以执行以下动作，由状态机管理。操作参照 WE2000 键位体系：

| 动作 | 触发方式 | 说明 | 优先级 |
|------|---------|------|--------|
| **慢跑** | 方向键 | 默认移动速度 | P0 |
| **加速冲刺** | 方向键 + R1 | 消耗体力的高速跑动，带球时步幅变大 | P0 |
| **带球** | 持球时移动 | 球有节奏地步点跟随，速度略低于无球 | P0 |
| **短传（×）** | 短传键 | 地面短传给队友 | P0 |
| **长传/传中（○）** | 长传键（蓄力） | 高空长传 / 边路传中 | P0 |
| **空档传球（△）** | 空档传球键（蓄力） | 直塞球穿透防线 | P0 |
| **射门（□）** | 射门键（蓄力） | 射门得分 | P0 |
| **停球** | 来球时自动 / 按短传键 | 将空中球控制在脚下 | P0 |
| **护球** | 持球时按住 L1 + 方向 | 背身护球，降低被断球概率，但移动慢 | P1 |
| **假动作** | 特定方向键组合 | 过人动作，晃开防守球员重心 | P2 |
| **头球** | 高空球时按射门/传球键 | 用头触球（攻门 / 摆渡） | P1 |
| **凌空射门** | 球在半空时按射门键 | 不等落地直接射门 | P2 |
| **倒钩** | 背对球门、球在身后高空时按射门键 | 高难度射门 | P3 |
| **铲球** | 无球时长传键（○） | 滑铲抢球，高风险高回报 | P0 |
| **逼抢** | 无球时按短传键（×） | 上前施压，跟随对方持球队员 | P0 |
| **切换球员** | 空档传球键（△） | 防守时切换到最近队友 | P0 |
| **门将扑救** | 门将专属 | 飞身扑救对方射门 | P0 |
| **门将出击** | 门将专属 / 射门键 | 主动出击封堵单刀 | P1 |
| **庆祝 / 失落** | 进球后自动 | 进球后的情绪反应 | P1 |

### 5.4 动作帧结构

**优先级：P1**

每个动作都有明确的帧结构（格斗游戏式设计）：

- **起手帧 (Startup)**：动作开始后的前几帧，可以被取消
- **判定帧 (Active)**：触球/有效帧，决定动作是否命中
- **收招帧 (Recovery)**：动作结束后的硬直，不可取消
- 高风险动作（铲球、射门）有较长的收招硬直作为风险代价

> **设计原则**：应该由硬直时长定义动画时长，而不是反过来。手感优先于动画美观。

### 5.5 身体对抗

**优先级：P2**

- 两名球员同时争抢球权时，通过数值规则判定谁获得球权
- 判定因素：身体力量、速度差、接触角度、当前动作状态
- 对抗结果：一方赢球、双方都没拿到（球被弹开）、或一方被撞倒（短暂硬直）
- 对抗不是物理碰撞模拟，而是数值规则计算的结果——可控、可调试

### 5.6 体力系统

**优先级：P3**

- 球员有体力值，随奔跑和剧烈动作消耗
- 体力低时：速度下降、动作变慢、失误率上升
- 体力在死球、慢跑、不持球时恢复
- 设计目的：制造比赛节奏的自然起伏，防止全程冲刺

### 5.7 多因子动作选择

**优先级：P1**

同一按键不等于同一动作。系统根据情境选择合适的动作变体：

**射门的评估维度：**

| 评估维度 | 影响的动作参数 |
|----------|-------------|
| 身体朝向 vs 球门方向 | 正脚背抽射 / 外脚背 / 勉强推射 |
| 防守压力（附近对手距离） | 正常射门 / 匆忙射门（变形动作） |
| 球速（来球速度） | 直接射 / 调整后射 |
| 球员能力（技术、射门、力量） | 动作库匹配（明星球员有专属参数） |
| 平衡状态 | 稳定射门 / 失去平衡捅射 |

> **核心**：不是"给每个球员录一套专属动画"，而是"动作模板 × 参数 = 行为差异"。参数差异让不同球员"感觉不一样"。

## 6. 人工智能系统（AI）

> **WE2000 AI 设计核心**：玩家只控制 1 人，场上其他 21 人全靠 AI。AI 才是足球游戏技术的核心。
>
> 由于采用「控球权自动切换」机制（见 3.2），**玩家方的持球队员永远是玩家自己操控**，所以玩家方 AI 的职责是「无球跑位 + 防守站位」，而不是「持球决策」。持球 AI 只对对方 CPU 球队和表演赛模式生效。

### 6.1 AI 分级架构（LOD）

**优先级：P1**

不是所有球员每帧都做完整决策，而是按距离球的远近分级。22 名球员中，大部分时间只有 2-3 人在做完整决策：

| 级别 | 球员范围 | 更新频率 | 决策内容 |
|------|---------|---------|---------|
| **核心层** | 离球最近的 2-3 人（含持球人） | 每 3 帧 | 完整决策（仅 CPU 持球方）/ 贴身防守 |
| **中间层** | 距离球中等的 6-8 人 | 每 15 帧 | 跑位、盯人、向归位点移动 |
| **远端层** | 远离球的 10+ 人 | 每 60 帧 | 阵型归位、小幅度晃动 |

> **设计原则**：远端球员不需要"思考"，只需要"站在那儿"。AI 的性能预算应该花在离球最近的球员身上。

### 6.2 归位点系统

**优先级：P2**

- 每个球员有一个"阵型位置"（home position），由阵型决定
- 球移动时，整支球队的阵型位置跟着整体平移和压缩
- 攻防转换时，阵型整体前压或后撤
- 不同角色的归位点偏移不同（前锋压得更靠前，后卫收得更靠后）
- 没有特殊任务的球员默认向归位点移动

### 6.3 玩家方队友 AI（无球进攻跑位）

**优先级：P0**

> 这是 WE2000 体验的核心：玩家只控一人，但队友像真人一样"懂你在干嘛"。玩家的进攻决策质量 = 自己的操作 + 队友的跑位。

己方无球球员会主动跑位创造空间：

- **反越位前插**：在对方防线附近伺机前插，接直塞球
- **拉边**：中路拥挤时向边路拉开，创造宽度
- **回撤接应**：离持球人远时回撤要球，作为短传选项
- **插空当**：发现防守漏洞时向空档跑动
- **套边助攻**：边后卫在边前卫内切时沿边路插上
- **二次进攻**：射门后跟进补射

跑位不是每帧重新计算，而是有状态（保持/前插/拉边/回撤），状态切换有冷却时间，避免抖动。

### 6.4 CPU 持球 AI（对方进攻）

**优先级：P1**

仅对 CPU 控制的持球球员生效（对方球队、表演赛模式）。

CPU 持球队员根据以下优先级做决策：

1. **射门**：如果在射门范围内且角度好 → 射门
2. **直塞**：如果有队友前插且路线通透 → 空档传球
3. **短传**：如果附近队友位置更好 → 短传配合
4. **带球**：如果前方有空当 → 带球推进
5. **长传**：如果远端有队友空位且距离远 → 长传转移
6. **护球**：如果被紧逼 → 背身护球，等待队友接应

决策权重受球员属性和球队风格影响：
- 射门倾向高的前锋更愿意射门
- 传球倾向高的中场更喜欢分球
- 进攻型球队更愿意冒险直塞，防守型球队更保守

### 6.5 防守 AI

**优先级：P2**

防守球员的核心原则：**不追球，追路线**。

- **站位优先**：优先站在球和球门之间的关键位置，而不是冲上去抢球
- **危险度排序**：根据球员位置的射门覆盖角度，决定谁去上抢、谁保护
- **盯人防守**：对应位置的球员紧盯对方对应位置的球员
- **区域防守**：保持防线整体形状，不轻易脱离位置
- **协防补位**：队友被过掉时补位
- **造越位**：整条防线同步前压，制造越位陷阱
- **铲球时机**：只在有较高成功率时出脚，不乱铲

防守 AI 的行为受球队风格影响：
- 进攻型球队：高位逼抢，防线靠前
- 防守型球队：深度防守，防线靠后，等待反击

### 6.6 门将 AI

**优先级：P1**

- **站位**：根据球的位置调整自己在球门线前的位置（近门柱优先）
- **出击**：对方单刀时主动出击缩小角度
- **扑救**：对方射门时判断方向，飞身扑救
- **扑单刀**：面对近距离射门时快速倒地封堵
- **开球**：获得球权后，手抛球给近处队友或开大脚给远端
- 门将有专属的属性：反应、手控球、出击

### 6.7 球队风格与战术

**优先级：P3**

不同球队有不同的整体战术倾向，影响全体 AI 的行为参数：

| 风格 | 防线位置 | 逼抢强度 | 传球偏好 | 射门倾向 |
|------|---------|---------|---------|---------|
| **进攻型** | 靠前 | 强 | 短传渗透 | 高 |
| **防守型** | 靠后 | 弱 | 长传反击 | 低 |
| **控球型** | 中等 | 中 | 短传倒脚 | 中 |
| **冲击型** | 中等 | 强 | 长传冲吊 | 中高 |

同一套 AI 系统，参数不同 = 风格不同。

### 6.8 难度等级

**优先级：P2**

AI 难度分为简单 / 普通 / 困难三档，影响以下参数：

| 维度 | 简单 | 普通 | 困难 |
|------|------|------|------|
| 射门精度 | 偏低 | 正常 | 偏高 |
| 传球精度 | 偏低 | 正常 | 偏高 |
| 反应速度 | 慢 | 正常 | 快 |
| 跑位合理性 | 一般 | 正常 | 优秀 |
| 防守紧逼度 | 松 | 正常 | 紧 |
| 失误频率 | 高 | 正常 | 低 |

> **设计原则**：难度不是"作弊式"的数值碾压，而是行为的合理性差异。简单 AI 会做蠢事（跑位失误、传球失误），困难 AI 决策更合理。

## 7. 误差与不确定性系统

### 7.1 设计原则

**优先级：P2**

- 不追求 100% 准确的传球和射门——误差是刻意设计的游戏系统
- 误差是**可控的、有原因的**，不是纯随机
- 玩家能理解"为什么传偏了"（防守压力大、球员技术差、匆忙出脚）
- 误差使用种子随机数——可复现，但不可预测

### 7.2 传球误差

误差大小由以下因素决定：

| 因素 | 影响 |
|------|------|
| 球员技术 | 技术越高，误差越小 |
| 传球距离 | 距离越远，误差越大 |
| 防守压力 | 附近有对方球员时，误差增大 |
| 动作状态 | 跑动中传球 > 站稳传球的误差 |
| 体力 | 体力低时误差增大 |

### 7.3 射门误差

- 类似传球误差，但以"偏离瞄准方向的角度"来计算
- 射门精度属性是主要影响因素
- 远射的误差显著大于禁区内射门
- 匆忙射门（被干扰时）误差翻倍

### 7.4 停球误差

- 来球质量差（速度过快、角度别扭）时，第一次触球会有误差
- 技术好的球员停球离脚近，技术差的球会弹远
- 停球误差创造了"抢断机会"——防守球员可以利用对方的停球失误上抢

## 8. 反馈与手感系统

### 8.1 冲击停顿（Hitstop）

**优先级：P0**

- 高冲击力的事件（射门、铲球命中、扑救）触发短暂的全局停顿
- 停顿时间与冲击力度正相关：轻碰撞 50ms，重铲球 100ms，大力射门 150ms
- 目的：制造"打击感"，让玩家感知到碰撞的重量
- 停顿期间游戏树暂停，但 UI 和音效不受影响

### 8.2 屏幕震动

**优先级：P2**

- 强烈事件伴随轻微的屏幕震动
- 震动幅度与事件强度匹配
- 震动时间短（100-300ms），不影响操作

### 8.3 粒子特效

**优先级：P2**

- 射门时的火花、铲球时的尘土、进球时的庆祝粒子
- 强化动作的视觉反馈
- 粒子数量控制在性能可接受范围内

### 8.4 音效反馈

**优先级：P0**

- 每个动作都有对应的音效：传球声、射门声、铲球声、接球声、弹跳声、哨声
- 音效的音量和音调随动作强度变化
- 进球时观众欢呼声的大小随进球精彩程度变化

### 8.5 UI 提示

**优先级：P1**

- 蓄力条：显示当前射门/传球的蓄力程度
- 传球目标高亮：辅助瞄准时，目标队友脚下/前方有指示
- 控球指示：当前控制球员头顶有箭头标识
- 球路预测（可选）：显示球的落点预判（辅助功能，可关闭）

### 8.6 球员状态指示

**优先级：P2**

11 人制下球员数量多，需要让玩家快速识别场上信息：

- **球员号码**：球员球衣背后显示号码，HUD 中可关联
- **当前控制标识**：玩家控制的球员头顶有明显箭头
- **接应示意**：队友跑位接应时，头顶有简短提示（如"要球"的小图标）
- **越位线**：可选的越位线可视化（辅助功能）
- **体力状态**：体力低的球员脚下颜色变化或图标提示

### 8.7 雷达小地图

**优先级：P1**

11 人制比赛的必需品——让玩家随时掌握全局态势：

- 位于屏幕角落（默认左下角）
- 显示所有球员的位置（己方亮色/对方暗色）和球的位置
- 显示当前控制球员的高亮标识
- 显示球场边界和禁区线
- 雷达视野范围跟随球场实际尺寸
- 可在设置中调整位置或关闭

## 9. 比赛流程系统

### 9.1 赛前

**优先级：P0**

- 选择模式（单人 / 双人对战 / 双人合作 / 表演赛）
- 选择球队（8 支国家队可选）
- 选择阵型和首发阵容
- 显示双方球队信息
- 3-2-1 倒计时开场

### 9.2 上半场

**优先级：P0**

- 比赛进行，计时器倒计时（默认 1 分钟 = 半场）
- 实时比分和时间显示在屏幕顶部
- 进球后短暂庆祝 → 重新开球
- 可暂停比赛（调出暂停菜单）

### 9.3 半场休息

**优先级：P2**

- 上半场结束后进入半场休息界面
- 显示上半场统计（比分、控球率、射门数）
- 可进行换人调整（最多换 3 人，全场累计）
- 可调整战术倾向（进攻/防守档位）
- 半场休息有时间限制（可选跳过）
- 双方交换场地

### 9.4 下半场

**优先级：P0**

- 交换场地后继续比赛
- 规则与上半场相同
- 终场哨响后进入结算

### 9.5 暂停菜单

**优先级：P0**

- 继续比赛
- 重新开始
- 退出到主菜单
- 设置调整（音量等）

### 9.6 换人系统

**优先级：P2**

11 人制标配：

- 全场最多 3 次换人名额
- 死球状态时才能换人（出界、进球、暂停时操作）
- 被换下的球员不能再上场
- 换人有短暂的场上动画（球员走下场/上场）
- 用于调整战术或替换体力不支的球员

### 9.7 赛后

**优先级：P1**

- 显示最终比分
- 显示比赛统计（进球数、控球率、射门次数、犯规——如有）
- 显示最佳球员（MVP）
- 选项：重赛 / 选队重赛 / 返回主菜单

## 10. UI / HUD 系统

### 10.1 主菜单

**优先级：P0**

- 标题画面

## 14. 非功能性需求

### 14.1 性能

- 所有文字清晰可读（像素字体）

## 附录 B：反模式清单

以下是设计中明确**不要做**的事情，记录在此作为决策参考：

| 反模式 | 为什么 |
|--------|--------|
| 用物理引擎做球运动 | 失去确定性，AI 无法预判落点。WE 的 AI 强就强在能预判球路。 |
| 用物理碰撞做触球判定 | "脚碰到了球吗"应该由动画帧决定，不是碰撞事件。物理碰撞的结果不可预测也不可调试。 |
| 让 AI 每帧都为所有球员决策 | 性能浪费 + 设计问题。远端球员不需要"思考"，只需要"站在那儿"。 |
| 追求物理真实参数 | 如果"真实值"导致手感差，直接 overrule 真实值。 |
| 让动画时长定义硬直 | 应该反过来——硬直时长定义动画时长，不要让美术决定手感。 |
| 追求 100% 传球准确率 | 完美的数学传球反而没有足球味——误差创造比赛的故事感。 |
| 给所有球员同一套动作参数 | 同质化是足球游戏的大敌——不同球员应该行为不同，不是数值不同。 |
| 为「更好看」牺牲「更好判定」 | 优先级：AI > 球物理 > 判定规则 > 手感系统 > 动画 > 细节。 |
