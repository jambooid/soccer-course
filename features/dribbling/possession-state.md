# "持有状态"机制 (Possession State)

## 设计理念

在无对抗情况下，球员和球应该是一个整体，球不会随意与球员分离。

## 问题场景

### 修复前
```
1. 球员往前带球（速度 80px/s）
2. 松开按键
3. 球员立即停止（0.1秒内）
4. 球因为惯性继续往前滚
5. 结果：球和球员分离
```

**问题**：不符合真实足球，也不符合 WE2000 的手感。球员不应该"扔下"球独自停止。

### 修复后（持有状态）
```
1. 球员往前带球（速度 80px/s）
2. 松开按键
3. 球员跟随球的速度（速度匹配球速 × 0.9）
4. 球员和球一起减速
5. 结果：球和球员一起静止，球在脚下
```

**效果**：球员"陪着"球停下，视觉上看起来球员在控制着球的停止过程。

## 实现细节

### 触发条件
1. 球员持球（`player.has_ball()`）
2. 无方向输入（松开 WASD/箭头键）
3. 无对抗（没有对方球员在抢）

### 行为逻辑

```gdscript
if player.has_ball():
    var ball_velocity := ball.velocity.length()
    if ball_velocity > 5.0:
        # 球还在移动 → 跟随球速度
        var target_velocity := ball.velocity * 0.9
        player.velocity = player.velocity.lerp(target_velocity, 0.3)
    else:
        # 球几乎静止 → 快速停下
        player.velocity = player.velocity.move_toward(Vector2.ZERO, speed * 8.0 * delta)
else:
    # 无球 → 正常快速停下
    player.velocity = player.velocity.move_toward(Vector2.ZERO, speed * 8.0 * delta)
```

### 参数说明

| 参数 | 值 | 说明 |
|-----|-----|------|
| 跟随倍率 | 0.9 | 球员速度是球速的 90%，让球保持在前方 |
| 插值系数 | 0.3 | 球员速度逐渐匹配球速，不是瞬间 |
| 停止阈值 | 5.0 px/s | 球速低于此值时，球员快速停下 |
| 停止系数 | 8.0 | 球几乎静止时的减速系数 |

## WE2000 对比

### WE2000
- 松开按键 → 球员和球一起滑行
- 球员似乎在"陪着"球
- 最终一起停下
- 球始终在脚下

### 我们的实现
- ✅ 球员跟随球速度（0.9× 倍率）
- ✅ 一起减速
- ✅ 最终一起停下
- ✅ 球在脚下

**匹配度**：非常接近 WE2000 的手感

## 与其他机制的配合

### 1. 方向跟随修正
- 持有状态主要处理**停止**过程
- 方向跟随处理**转向**过程
- 两者互补，覆盖所有无对抗场景

### 2. 失控判定
- 持有状态下，球和球员距离保持在 10px 左右
- 远小于 100px 的失控边界
- 不会误触发失控

### 3. 自动接球
- 持有状态确保球不会离开球员
- 自动接球处理球滚到脚边的情况
- 两者共同确保"球权稳定"

## 对抗情况的处理

**重要**：持有状态只在**无对抗**时生效。

当有对方球员接近时：
- `BallStateDribbling` 的抢断检测会触发
- 如果被抢断成功 → 球权转移，持有状态自动失效
- 如果抢断失败 → 持有状态继续

所以持有状态不会影响对抗逻辑。

## 参数调优指南

如果需要调整手感：

### 球员跟得太紧/太松
- 调整 `target_velocity := ball.velocity * 0.9`
- 更大的倍率（0.95）→ 跟得更紧
- 更小的倍率（0.85）→ 球更往前

### 跟随太快/太慢
- 调整 `lerp(target_velocity, 0.3)`
- 更大的系数（0.5）→ 更快匹配
- 更小的系数（0.1）→ 更平滑

### 停止太慢
- 调整停止阈值 `ball_velocity > 5.0`
- 更大的阈值（10.0）→ 更早进入快速停止
- 更小的阈值（2.0）→ 更晚进入快速停止

## 技术要点

### 为什么用 lerp 而不是直接设置？
- `player.velocity = ball.velocity * 0.9` → 瞬间匹配，不自然
- `lerp(target, 0.3)` → 逐渐匹配，更平滑

### 为什么是 0.9× 而不是 1.0×？
- 1.0× → 球员速度 = 球速，球不在前方
- 0.9× → 球员略慢，球保持在前方（视觉上更自然）

### 为什么有停止阈值？
- 球速很低时（<5px/s），继续跟随会导致"蠕动"
- 低于阈值时切换到快速停止，干脆利落

## 总结

**持有状态机制**是实现"球随人走"手感的最后一块拼图：

1. ✅ **球离身体近**（触球区缩小）
2. ✅ **转向不丢球**（方向跟随修正）
3. ✅ **停下不分离**（持有状态） ← 本次新增

三者结合，实现了 WE2000 级别的带球手感。
